# Design

## Context

- この RIS は DICOM の MWL・MPPS の SCP と、予約の作成を持つ。HL7 は扱わない
- 送る相手は、開発の一式の PACS 側の受け口（tsunagi）。受け口は別の change で作る。
  このため、2 つの実装が同じ例を見て合わせられるように、メッセージの例を docs に残す
- IHE RAD TF-2 の表（4.1・4.4・4.12・2.4）が、必須の欄と値を決める。HL7 v2.3.1 の原典は
  手元で読めていない

## Goals / Non-Goals

**Goals:**

- IHE の必須の欄を満たす v2.3.1 の ADT^A40・ADT^A08・ORM^O01 を、再現できる形で組み立てる
- 通信の誤りと相手の拒否を、呼び出し側が分けて扱える結果で返す

**Non-Goals:**

- 受信、ACK を返す側の実装
- 送信結果の保存・再送（照合の change で扱う。結果の型はそのまま保存できる形にしておく）
- v2.5.1、A02・A03・A06・A07、RAD-13 の CA・DC・XO

## Decisions

### 組み立ては自前で行い、ライブラリを足さない

メッセージは 3 種類で、欄の位置は IHE の表で決まる。値は 1 つずつ `escape` を通し、
欄の位置は試験で固定する。ADR-0010 に理由を書く。

### 漢字は UTF-8 の MSH-18、氏名は表記ごとの XPN の繰り返し

IHE は文字集合の切り替え（MSH-20）を認めないので、ISO IR87 のエスケープ列は使わない。
MSH-18 は ASCII だけのメッセージでは空にする（IHE RAD TF-2 2.4.2.2）。氏名は英字・漢字・かなを
XPN の繰り返しにし、名前の種類 `L`、表記の種類 `A`・`I`・`P` を付ける。XPN の 8 つめの
表記の種類は、v2.3.1 の原典で確認していない。受け手が読めなければ順番で判断できる。

### 層：組み立ては Core、通信は `app/hl7/`

組み立てと ACK の読み取りはファイル・通信を使わないので、`app/core/hl7.py` に置き、
通信なしで試験する。ソケットの送受信は `app/hl7/mllp.py` に分け、スタブの受け手で試験する。

### 結果は例外にせず値で返す

`send_message` は、接続できない・時間切れ・枠の誤り・ACK の誤り・MSA-2 の不一致・想定外の
確認コードを `failed`、AE・AR を `rejected`、AA を `accepted` として返す。照合の change が
「失敗」を予約に記録して再送できるようにするため。再接続と再送は、この change では行わない。

### PV1 と来院番号

IHE は PID-18 か PV1-19 のどちらかに値を求める。A08 と ORM は来院番号か患者アカウント番号が
無ければ断る。CLI は ORM の来院番号を指定しなければ、受付番号を使う。A40 は PV1 が任意なので付けない。

### 宛先の設定

設定の `hl7` に宛先と MSH の名前を持つ。節が無い設定は既定値（`127.0.0.1:2575`）で読み、
`pir send` を使わない利用者の設定を壊さない。CLI の `--host`・`--port` で上書きできる。

## Risks / Trade-offs

- [XPN の 8 つめ、CX の 5 つめ、`UNICODE UTF-8` が v2.3.1 に無いかもしれない] → docs の
  「確認していないこと」に書く。受け手が読めなければ ADR-0010 を見直す
- [IHE の v2.3.1 の表の欄の長さを超える（PID-3 は 20）] → 守らない。受け手が長さを検査する
  ときに分かるよう docs に書く
- [MLLP に認証が無い] → 宛先は設定した 1 か所だけで、開発・試験の環境に限る
  （憲章の範囲）。受け手の側が送り手の住所を絞る

## Migration Plan

1. 追加のみで、既存の動作は変わらない。`hl7` の節の無い設定も読める
2. 戻すときは、この change の commit を revert する
