# Design

## Context

一覧の列と状態の選択欄が多く、予約の補足と操作が同じ表に混在している。
既存の期間、100 件のページ、古い `date` の別名、状態の遷移の規則は保つ。

## Goals / Non-Goals

一覧で予定を把握し、選んだ予約の区画で補足の確認・状態変更・詳細への移動・撮り直しを行う。
ページサイズの選択や上の帯の検索などの機能は追加しない。

## Decisions

- 選択は `selected` の受付番号を URL に持ち、ページ内に無ければ先頭を使う。
  ページ送りで選択は外し、状態・モダリティ・q を保つ。本日は従来どおり `/orders` に戻る
- 状態別の件数は状態の条件を付けない SQL の GROUP BY で数え、全状態を 0 で補う
- q は前後の空白を除き、患者ID または受付番号をパラメーターで完全一致検索する
- htmx の状態変更はフォームから送る。204 と HX-Refresh で行・件数・区画を同時に更新する
- 失敗時はフォーム内の `select[data-current]` を戻し、上部の知らせを出す
- 右の区画は 360px、900px 以下では一覧の下へ回す。既存の共通クラスは残す

## Risks / Trade-offs

状態変更の成功時にページ全体を読み直すため、スクロール位置はブラウザの動作に従う。
ソケットを禁止する実行環境では通信試験と TestClient の実行を完了できないため、
全試験の合格はソケットの使える環境で確認する必要がある。
