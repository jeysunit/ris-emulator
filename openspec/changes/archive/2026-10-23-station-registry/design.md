# Design

## Context

- 装置は今、設定の `orders.modalities.<モダリティ>` の `station_ae_titles`（AE タイトルの
  並び）と `station_name`（1つ）で持つ。予約ごとに `station_ae_titles` を順に使い、装置名は
  モダリティで1つに決まる
- 予約の作成の要求（`OrderRequest`）は `station_ae_title` を1つだけ持ち、件数を入れた
  すべてのモダリティに同じ値を入れる
- 設定は起動のときに1回読み、凍結したモデル（pydantic の `frozen`）で持つ。画面から
  設定を書き換える機能は無い

## Goals / Non-Goals

**Goals:**

- 装置の名前・AE タイトル・装置名・モダリティの組を1か所で持ち、組がずれないようにする
- 予約の画面と CLI で、モダリティごとに装置を選べるようにする

**Non-Goals:**

- 画面からの台帳の追加・変更・削除
- 1つの装置で複数のモダリティを扱う形（PET/CT など）。必要なら、同じ AE タイトルの装置を
  それぞれのモダリティの台帳に書く
- Scheduled Procedure Step Location (0040,0011) など、装置に付く他の属性

## Decisions

### 台帳は設定ファイルに持つ（推奨）

案は2つある。

| 案 | 持ち方 | 長所 | 短所 |
|----|--------|------|------|
| A（推奨） | 設定ファイル（`orders.modalities.<モダリティ>.stations`） | 今の作り（設定は YAML、画面は予約だけを扱う）に合う。Docker では設定ファイルをマウントして替える。検証は読み込みの1か所 | 変えるには再起動が要る |
| B | データベースの表と、画面の台帳の編集 | 再起動なしで変えられる | 表・画面・CSRF の付いた編集の画面・削除した装置を参照する予約の扱いが要る。試験の範囲が広がる |

試験の環境では装置の構成は頻繁に変わらないので、A にする。B が要るときは、A の台帳を
初期値として表に移す形で後から足せる。

### 台帳はモダリティの下に置く

`stations` を `orders.modalities.<モダリティ>` の下に置き、装置の `modality` の欄は持たない。
モダリティを欄で持つと、台帳のモダリティと検査の種類（`procedures`）のモダリティが
食い違う設定が書けてしまう。

### 古いキーは変換せずに断る

`station_ae_titles` と `station_name` から `stations` を作る変換も考えたが、名前の欄の値を
推測で決めること（AE タイトルを名前にする）になり、画面に出る名前が利用者の意図と
違ってしまう。設定のエラーで止め、書き換えの例を示す。既定の設定とイメージの中の設定は、
この change で新しい形にする。

### 予約の要求は、モダリティごとの装置の名前を持つ

`OrderRequest.station_ae_title` を `stations: dict[str, str]`（モダリティ → 装置の名前）に
替える。サービスの層で、名前が台帳のそのモダリティにあるかを確かめる。画面のフォームは
`station_<モダリティ>` の欄で送る。

### 予約に装置の名前を残す

`Order` に `scheduled_station_label: str = ""` を足す。予約の内容は JSON の列（`body`）に
入っているので、表の形は変えない。読み込んだ古い予約は空の値になり、表示では AE タイトルで
代える。

## Risks / Trade-offs

- [自分の設定ファイルを使う利用者の起動が止まる] → エラーの文に新しい形の例を出し、
  `docs/usage.md` に書き換えの例を書く。リリースの説明に BREAKING と書く
- [装置名（SH）に日本語を書くと、文字コードによって書けない] → 今の
  「文字コードで表せない文字」の検証（`docs/spec/01_orders.md` の 3.3）が予約の作成の
  ときに止める。既定の台帳の装置名は英数字にする

## Migration Plan

1. 既定の `config/app_config.yaml` を新しい形にする（CT1号機 / CT01 / CT01 など、各モダリティ1台）
2. 自分の設定ファイルを使う利用者は、`station_ae_titles` の各値を `stations` の1項目にし、
   `name` を付ける
3. 戻すときは、この change の commit を revert し、設定ファイルを古い形に戻す。
   保存した予約の `scheduled_station_label` は、古い版では読み飛ばされる
