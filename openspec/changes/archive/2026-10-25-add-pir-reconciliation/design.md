# Design

## Context

- RIS は MPPS の N-CREATE で、一致する予約の無い項目を「予定の無い撮影」として、MPPS の
  記録だけ残す。記録には、モダリティが入力した患者と Study Instance UID（Scheduled Step
  Attributes Sequence の中）が入っている
- HL7 の組み立てと MLLP の送信は `add-pir-hl7-sender` で作った。結果は例外にせず、受理・
  拒否・失敗の値で返す
- 受け手は tsunagi-dicom の HL7 の受け口。同じ送り手・同じ MSH-10 のメッセージの再送には、
  Orthanc を呼ばずに前と同じ ACK を返す

## Goals / Non-Goals

**Goals:**

- 未照合の撮影に、撮影の Study Instance UID を保ったまま、正式な患者と予約を結ぶ
- 結び付けと HL7 の組み立てを失敗なく 1 回で確定し、送信の失敗で照合を取り消さない
- 送信の結果を残し、同じ本文で再送信できる

**Non-Goals:**

- 照合の取り消し、Case 6（照合の後の追加の画像）、RAD-13、複数の予約を 1 つの撮影に結ぶこと

## Decisions

### MPPS の記録に新しい予約を結ぶ

MPPS の記録の「結び付いた受付番号」に新しい予約を足す。MPPS の本体は変えない。N-SET が
届いたときに、既存の処理（ADR-0007）が新しい予約の状態を進める。未照合の一覧は「結び付いた
受付番号が空」の MPPS で、結び付けた後は自然に外れ、2 回目の照合は断る。
ADR-0011 に理由を書く。

### Study Instance UID は撮影の値

予約を作るときに発番する ADR-0004 の例外。PIR では撮影・画像・HL7 を同じ UID で結ぶので、
RIS が発番し直すと PACS の画像と食い違う。

### 1 つのトランザクションで、予約・結び付け・HL7 の組み立てまで

`OrderStore.reconcile_mpps` が、連番の取得、予約の保存、MPPS への結び付け、照合の記録を
行う。予約と送る HL7 を組み立てる関数を渡し、その中で HL7 を組み立てる。組み立てが断れば
（氏名が空、発番元が空など）、何も残さず、連番も使わない。HL7 は確定のときの本文を記録に
保存し、送信は後から行う。

### 送信は順に行い、受理されなかった 1 通で止める

A40 が拒否されたまま ORM が届くと、PACS の患者と予約が食い違う。止めた通より後の通は
「送信待ち」で残し、再送信が先頭の受理されていない通から送る。

### 再送信は同じ本文

記録した本文と MSH-10 をそのまま送る。受け手が MSH-10 で重複を見分けるとき、結果が
分からなかった送信（時間切れなど）の再送が二重に反映されない。

### 画面と CLI

画面は「未照合」の一覧と照合の画面、予約の詳細の「HL7 送信」の表。CLI の `reconcile`
は、パスワードを渡せない場面（Docker の中、自動の試験）でも同じ操作ができるようにする。
画面の言葉は screen-terms に従い、説明の文は置かない。

## Risks / Trade-offs

- [送った本文の保存に患者の氏名が残る] → 架空の患者だけで使う前提（憲章）
- [A40 の後に ORM を送る順序が、IHE の必須かどうかを読み切っていない] → spec の
  「確認していないこと」に書く。受け手が順序を求めなければ、止める規則を見直す
- [優先度 STAT・患者区分 E は RIS の判断] → spec に書く。設定にはしない
- [MPPS が IN PROGRESS のうちに照合すると、予約は実施中になる] → 後の N-SET で完了になる。
  実施中の予約は MWL で返る（設定の `mwl.statuses`）が、撮影はもう済んでいる。
  必要なら画面・CLI で状態を変える

## Migration Plan

1. 追加のみ。`reconciliations` の表は起動のときに作る。古いデータベースはそのまま読める
2. 戻すときは、この change の commit を revert する。作られた表は残るが、使われない
