# Spec Delta

## MODIFIED Requirements

### Requirement: 状態は遷移の表のとおりに変更する

予約の状態は、次の表で「可」とした向きにだけ変更しなければならない（SHALL）。
行が今の状態、列が変更後の状態。完了・取消・中止は終わりの状態で、ほかの状態へ変更しない
（HL7 v2 の Table 0038 Order Status でも、CM（完了）・CA（取消）・DC（中止）は終わりの状態）。
この表は、画面・CLI の手動の変更と MPPS による変更の両方に使う。例外は1つで、
`orders.retake_policy` が `same_study` のときだけ、MPPS の N-CREATE による「中止 → 実施中」を許す
（`mpps-scp`）。手動の変更では許さない。

| 今の状態 | 予定 | 実施中 | 完了 | 取消 | 中止 |
|----------|------|--------|------|------|------|
| 予定 | - | 可 | 可 | 可 | 不可 |
| 実施中 | 可 | - | 可 | 可 | 可 |
| 完了 | 不可 | 不可 | - | 不可 | 不可 |
| 取消 | 不可 | 不可 | 不可 | - | 不可 |
| 中止 | 不可 | 不可 | 不可 | 不可 | - |

#### Scenario: 予定から実施中へ変更する

- **WHEN** 利用者が、予定の予約を CLI の `status <受付番号> in_progress` で変更する
- **THEN** 予約の状態は実施中になり、終了コードは 0 になる

#### Scenario: 実施中から予定へ戻す

- **WHEN** 利用者が、実施中の予約を画面で予定に変更する
- **THEN** 予約の状態は予定になり、MWL の応答の Scheduled Procedure Step Status は `SCHEDULED` になる

#### Scenario: 完了の予約を予定に戻そうとする

- **WHEN** 利用者が、完了の予約を CLI の `status <受付番号> scheduled` で変更しようとする
- **THEN** 予約の状態は完了のままで、終了コードは 2 になり、標準エラーに今の状態と変更できないことが出る

#### Scenario: 取消の予約を実施中にしようとする

- **WHEN** 画面から、取消の予約の状態を `in_progress` にする POST が届く
- **THEN** 応答は 400 になり、予約の状態は取消のまま、更新日時も変わらない

#### Scenario: 予定の予約を中止にしようとする

- **WHEN** 利用者が、予定の予約を CLI の `status <受付番号> discontinued` で変更しようとする
- **THEN** 予約の状態は予定のままで、終了コードは 2 になる

#### Scenario: 中止の予約を予定に戻そうとする

- **WHEN** 画面から、中止の予約の状態を `scheduled` にする POST が届く
- **THEN** 応答は 400 になり、予約の状態は中止のままになる

#### Scenario: same_study でも中止を手動で実施中に戻せない

- **WHEN** `same_study` の設定で、利用者が中止の予約を CLI の `status <受付番号> in_progress` で変更しようとする
- **THEN** 予約の状態は中止のままで、終了コードは 2 になる
