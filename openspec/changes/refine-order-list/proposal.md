# Proposal

## Why

承認者が 2026-10-24 に予約の一覧の画面を見て、次の5点を指摘した。

- ページの題とナビの「予約の一覧」「予約を作る」は、業務アプリの題として回りくどい。
  「予約一覧」「予約作成」にする
- 今日の予約に戻るボタンが無い。予定日を本日、状態とモダリティをすべてにして表示する
  「本日」のボタンが要る
- 「全日付」は、予約が少ないうちは使えるが、たまると1画面に全件が並んで使いにくくなる。
  今の一覧には期間の指定も件数の上限も頁送りも無い
- フッターの「ris-emulator 0.1.0・開発・試験用（本物の患者のデータは入れない）」は、
  業務アプリの画面に付いている帯として不自然
- 状態の列の幅が固定されていない。選択肢のある行（予定・実施中）と無い行（完了・取消・中止）で
  セルの中身の幅が違うので、絞り込みや状態の変更のたびに列の幅が変わってちらつく

## What Changes

- 題とナビの言葉を「予約一覧」「予約作成」にする。予約の詳細の「予約の一覧へ」のリンクと、
  一覧が空のときの「予約を作る」のリンクも同じ言葉にする
- 絞り込みのフォームに「本日」のボタンを足す。押すと、予定日を本日、状態とモダリティを
  すべてにした一覧を表示する
- 「全日付」をやめ、予定日を期間（開始日〜終了日、31日まで）で指定できるようにする。
  「前日」「翌日」のボタンで期間を1日ずつ動かす。一覧は 100 件ずつの頁に分け、
  全体の件数と頁送りを出す
- フッターの帯を外す。版はヘッダーの製品名の横に小さく出す。開発・試験用であることの断りは、
  画面には出さず、README と設定ファイルのコメントに残す（どちらにも既にある）
- 状態の列の幅を固定し、選択肢の有無と状態の変更で列の幅が変わらないようにする

## 承認者が決めること

1. 「全日付」の代わりの方式
   - 案 A（推奨）：期間の指定（31日まで）と「前日」「翌日」、100 件ずつの頁送り。
     日ごとに確かめる使い方（RIS の当日の受付の一覧と同じ）を保ちつつ、数日分も見られる
   - 案 B：「全日付」を残し、頁送りだけを足す。たまっても1頁は軽いが、目当ての日を探すのに
     頁をめくることになる
   - 案 C：「全日付」を残し、新しい順の上限 500 件で打ち切る。作るのは最も小さいが、
     古い予約が見えなくなる
2. 版と「開発・試験用」の断りの置き場所
   - 案 A（推奨）：版はヘッダーの製品名の横に小さく出す。断りは画面から外し、README と
     設定ファイルのコメントに置く。業務アプリでも版を画面の隅に出す例は多く、
     利用者が不具合を報告するときに版を確かめられる
   - 案 B：版も画面から外し、`python -m app.cli version` と README だけにする
   - 案 C：ヘッダーに「試験用」の小さな印を出す（版は案 A と同じ）。本物の RIS の画面と
     並べて開いたときに取り違えにくいが、承認者の指摘した「帯」に近い

## Capabilities

### New Capabilities

- `order-list`: 予約一覧の画面の題・絞り込み（本日・期間・前日と翌日）・頁送り・
  状態の列・画面の枠（ヘッダーとフッター）

### Modified Capabilities

（なし。`screen-terms` の一覧の見出しの要件は変えない）

## Impact

- コード：`app/web/app.py`（`/orders` の期間と頁の引数）、`app/web/templates/base.html`・
  `orders.html`・`_order_row.html`・`order_detail.html`、`app/web/static/app.css`
- テスト：`tests/web/` に、題・本日・期間・頁送り・フッターが無いこと・状態の列の試験を足す
- ドキュメント：`docs/spec/03_web_cli.md` の 3.1 の表と 3.2 の画面の文言
- CLI の `list`・MWL・データベースは変わらない
