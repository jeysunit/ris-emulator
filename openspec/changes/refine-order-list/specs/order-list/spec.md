# Spec Delta

## Purpose

予約一覧の画面で、予約を日ごと・期間ごとに絞り込んで見る操作と、画面の枠（題・ヘッダー・
フッター）の表示を定める。

## ADDED Requirements

### Requirement: 題とナビの言葉

ナビ・ページの題（`<title>`）・見出しは、一覧の画面を「予約一覧」、予約を作る画面を
「予約作成」と書かなければならない（SHALL）。予約の詳細の画面から一覧へ戻るリンクは
「予約一覧へ」、一覧が空のときに予約を作る画面へ進むリンクは「予約作成」と書く。

#### Scenario: ナビの言葉

- **WHEN** 利用者がどの画面を開いても
- **THEN** ナビのリンクは「予約一覧」「予約作成」で、「予約の一覧」「予約を作る」の言葉は画面のどこにも出ない

#### Scenario: 一覧の題

- **WHEN** 利用者が一覧の画面を開く
- **THEN** ページの題と見出しは「予約一覧」になる

### Requirement: 本日のボタン

一覧の絞り込みのフォームに「本日」のボタンを置かなければならない（SHALL）。押すと、
予定日の期間を本日の1日、状態とモダリティをすべて、頁を1頁目にした一覧を表示する。
本日は、サーバーのローカル時刻（`TZ`）の日付とする。

#### Scenario: ほかの日を見た後に本日へ戻る

- **WHEN** 利用者が予定日を翌日・状態を完了・モダリティを CT にして表示した後に「本日」を押す
- **THEN** 本日のすべての状態・すべてのモダリティの予約が表示され、予定日の欄は本日、状態とモダリティの欄は「すべて」になる

### Requirement: 予定日の期間

一覧は、予定日を開始日と終了日の期間で絞り込まなければならない（SHALL）。期間は両端を
含み、31日までとする。開始日だけを指定したときは、その1日の予約を表示する。指定が
無いときは、本日の1日を表示する。終了日が開始日より前のとき、または期間が31日を超える
ときは、一覧を表示せず、理由を書いたエラーを出す（応答は 400）。

「前日」「翌日」のボタンは、今の期間の日数を保ったまま、期間を1日前・1日後へ動かす。
状態とモダリティの絞り込みは保つ。

「全日付」のボタンと、すべての日の予約を1度に表示する指定は置かない。

#### Scenario: 何も指定せずに開く

- **WHEN** 利用者が絞り込みを指定せずに一覧を開く
- **THEN** 本日の予約だけが表示される

#### Scenario: 期間で絞り込む

- **WHEN** 利用者が開始日を 2026-10-24、終了日を 2026-10-30 にして表示する
- **THEN** 予定日が 2026-10-24 から 2026-10-30 までの予約が、予定日時の順に表示される

#### Scenario: 31日を超える期間

- **WHEN** 利用者が開始日を 2026-10-01、終了日を 2026-11-15 にして表示する
- **THEN** 一覧は表示されず、期間は31日までであることを書いたエラーが出る

#### Scenario: 翌日へ動かす

- **WHEN** 利用者が期間 2026-10-24〜2026-10-25、状態を予定にした一覧で「翌日」を押す
- **THEN** 期間 2026-10-25〜2026-10-26、状態が予定の一覧が表示される

### Requirement: 頁送り

一覧は、絞り込みに合う予約を予定日時の順に 100 件ずつの頁に分けて表示しなければならない
（SHALL）。絞り込みに合う全体の件数と、今の頁の範囲（例「1〜100 件目／全 230 件」）を出し、
前の頁・次の頁へのリンクを置く。頁を動かしても絞り込みは保つ。頁の番号が範囲の外のときは、
最後の頁を表示する。

#### Scenario: 100 件を超える日

- **WHEN** 本日の予約が 230 件あり、利用者が本日の一覧を開く
- **THEN** 1〜100 件目が表示され、「1〜100 件目／全 230 件」と次の頁へのリンクが出る

#### Scenario: 最後の頁

- **WHEN** 利用者が同じ一覧の3頁目を開く
- **THEN** 201〜230 件目が表示され、次の頁へのリンクは出ない

### Requirement: 状態の列の幅

一覧の状態の列は、行に選択肢があるか（予定・実施中）、状態の名前だけか（完了・取消・中止）に
かかわらず、同じ幅でなければならない（SHALL）。行の状態を変えて行が置き換わったときも、
状態の列とほかの列の幅を変えない。状態の選択肢の幅は、列の幅いっぱいにする。

#### Scenario: 選択肢のある行と無い行

- **WHEN** 予定の予約と完了の予約が並ぶ一覧と、完了の予約だけの一覧を、同じ画面の幅で開く
- **THEN** 2つの一覧で、状態の列の幅は同じになる

#### Scenario: 状態を変えて行が置き換わる

- **WHEN** 利用者が一覧の行で状態を実施中から完了に変える
- **THEN** その行の状態は選択肢から名前だけに変わり、表の列の幅は変わらない

### Requirement: 画面の枠

画面の下に、版や開発・試験用であることの断りを書いた帯（フッター）を置いてはならない
（SHALL NOT）。版は、ヘッダーの製品名の横に、製品名より小さく出す。

#### Scenario: どの画面にも帯が無い

- **WHEN** 利用者が一覧・予約作成・予約の詳細の画面を開く
- **THEN** 画面の下に帯は無く、ヘッダーの製品名の横に版（例 `0.1.0`）が出る
