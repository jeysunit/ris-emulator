# Design

## Context

- 一覧の `/orders` は `date`（1日）・`status`・`modality` を受ける。`date=all` で全件を出し、
  日付が読めないときは黙って本日にしている。件数の上限は無い
- 保存の側（`OrderStore.list_orders`）は、既に `date_from`・`date_to` の範囲で絞れる
- 状態のセルは、終わりの状態なら名前だけ、そうでなければ `<select>` を出す。表は
  `width: 100%` の自動の幅で、セルの中身から列の幅を決める。htmx が行を置き換えると、
  中身の幅が変わった列に合わせて表の全体の幅が配り直される
- 公開の RIS の資料では、一覧は日ごとに見るのが基本になっている。県立病院の放射線の
  システムの調達仕様（2025 年）は、患者の「当日検査予約情報」の表示と受付、
  「カレンダー表示で予約の埋まり状況を一望できること」を求めている
  （<https://www.hospital.pref.ibaraki.jp/chuo/wp-content/uploads/2025/08/f6a6820e2a6fefd682a7686aba5a98ac-1.pdf>、
  2026-10-24 に読んだ）。予約の検索で日付の範囲を指定する例は、eRAD RIS の予約の手引き
  （<https://helpserver.erad.com/links/ER/RIS/en_US/9.9.9/Help/eRAD_RIS_Job_Aid_-_Scheduling.pdf>、
  2017 年版）にある

## Goals / Non-Goals

**Goals:**

- 予約がたまっても、一覧の1頁の重さと探しやすさを保つ
- 状態の列のちらつきを止める
- 画面の言葉と枠を業務アプリの普通の形にする

**Non-Goals:**

- カレンダーの表示（日ごとの件数の一望）。要るなら別の change にする
- CLI の `list` に期間と頁を足すこと
- 一覧の並べ替え・列の選択

## Decisions

### 期間は `date_from`・`date_to` の2つの引数にする

URL は `/orders?date_from=2026-10-24&date_to=2026-10-30&status=&modality=&page=1`。
今の `date` は `date_from` と同じ意味で受け、`date=all` は受けない（400）。
古いブックマークで `date=all` を開いたときに、黙って本日に読み替えると利用者が
気付かないので、エラーにする。31日の上限は、1か月分の予約を見る使い方を残しつつ、
期間の指定が全件の代わりにならない幅として決めた。

### 頁は保存の側の LIMIT と OFFSET で切る

`OrderStore.list_orders` に `limit`・`offset` を足し、件数は同じ条件の `COUNT(*)` で数える。
全件を読んでから画面で切ると、たまったときの重さが変わらない。並びは今と同じ
（予定日・予定時刻・登録の順）で、頁をまたいでも順が揺れない。

### 本日・前日・翌日はリンクにする

「本日」は `/orders`（引数なし）へのリンク、「前日」「翌日」は動かした期間の URL への
リンクにする。フォームの値を書き換えて送る JavaScript は要らない（CSP は `script-src 'self'`
のままで済む）。

### 状態の列は列の幅を CSS で固定する

状態の列の `th`・`td` に `class="col-status"` を付け、`width`・`min-width` を同じ値
（最も長い状態の名前と選択肢の矢印が収まる幅、目安 7em）にする。`select` は
`width: 100%`。表の全体を `table-layout: fixed` にはしない（患者氏名などの列は中身に
合わせたい）。状態の列の幅が中身に依らなくなれば、行が置き換わってもほかの列に配り直す
幅が変わらない。

### 版はヘッダーの製品名の横に出す

`base.html` のフッターを削り、`.brand` の横に `<span class="version">{{ version }}</span>`
を置く。「開発・試験用」の断りは README の「注意」と `config/app_config.yaml` の冒頭の
コメントに既にあるので、足さない。

## Risks / Trade-offs

- [`date=all` を使う既存のブックマークや手順が 400 になる] → README・`docs/` に `date=all` の
  記載が無いことを確かめる。エラーの文に期間の指定のしかたを書く
- [状態の列を固定の幅にすると、将来もっと長い状態の名前を足したときにはみ出す] →
  状態の名前を足す change で幅を見直す。試験で、すべての状態の名前が列に収まることを確かめる
- [頁の途中で予約が足されると、頁の境目の行がずれる] → 試験用の画面で、同時に書き込む
  利用者は少ない。ずれは表示だけで、データは変わらない
