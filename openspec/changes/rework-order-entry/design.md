# Design

## Context

今の予約を作る画面の欄が何のためにあるかを、コードで確かめた（2026-10-24）。

- 「順に使う」：装置を選ばないとき、台帳の装置を予約ごとに順に割り当てる
  （`slot % len(stations)`）。既定の台帳はモダリティごとに1台なので、今は選んでも
  選ばなくても同じ結果になる
- 「乱数で作る」：架空の患者を作る。「名簿から選ぶ」：予約ごとに名簿から無作為に1人を引く
  （`rng.choice(roster)`）。利用者が名簿の患者を指定する欄は無い
- 「シード」：乱数の種。同じ値なら、同じ患者・検査名・依頼科・依頼医の組み合わせを作る。
  空なら毎回変わる
- 検査名は、設定の検査の種類から乱数で選ぶ。利用者が選ぶ欄は無い

公開の RIS の資料で、予約を作る流れを確かめた（2026-10-24 に読んだ）。

- eRAD RIS の予約の手引き（<https://helpserver.erad.com/links/ER/RIS/en_US/9.9.9/Help/eRAD_RIS_Job_Aid_-_Scheduling.pdf>、
  2017 年版）の「新しい予約」は、患者を検索して選ぶ（無ければ新規の患者を登録する）→
  依頼の情報（紹介医・優先度など）→ 予約のタブで検査名を選ぶ → 検査に合う部屋（装置）を選ぶ →
  日付の範囲と時間帯で空いた枠を検索する → 枠を選ぶ、の順になっている
- 県立病院の放射線のシステムの調達仕様（2025 年、
  <https://www.hospital.pref.ibaraki.jp/chuo/wp-content/uploads/2025/08/f6a6820e2a6fefd682a7686aba5a98ac-1.pdf>）では、
  検査の予約（検査日時・検査種別・依頼医・依頼科など）は HIS のオーダから受け取り、RIS は
  受付と、カレンダーでの予約の状況の表示を受け持つ

ris-emulator には、HIS のオーダを受ける口も、装置ごとの予約枠も無い。そのため予約作成の画面は、
HIS のオーダと RIS の予約を1画面で兼ね、「患者 → 検査と装置 → 予定日時」の順にする
（承認者が決めること 1 の案 A。spec は推奨の案で書いた。案 B に決まれば、欄の順の要件だけを直す）。

## Goals / Non-Goals

**Goals:**

- 予約作成の画面を、1件の予約を作る実際の流れに合わせる
- 名簿の患者を、利用者が指定して予約できるようにする
- 試験データを大量に作る機能を残し、言葉を直す
- 時刻の分を、刻み（間隔）に合わせて選ばせる

**Non-Goals:**

- 装置ごとの予約枠（空き枠）の管理と、空いた時刻の検索
- 名簿の患者の追加・編集を画面から行うこと
- HL7 のオーダの受信（憲章で対象外）
- CLI の `create` の変更

## Decisions

### 予約作成は OrderRequest の1件として作る

予約作成の画面は、`OrderRequest(counts={モダリティ: 1}, stations={モダリティ: 装置}, ...)` に
2つの欄を足して送る。

- `procedure_code: str | None`：検査の種類のコード。指定があれば乱数で選ばない。
  選んだモダリティの `procedures` に無ければ `ValidationError`
- `roster_patient_id: str | None`：名簿の患者 ID。指定があれば名簿のその患者を使う。
  名簿に無ければ `ValidationError`

保存・採番・文字コードの確かめは今の `create_orders` をそのまま通る。新しい作成の経路を
作らないので、欠番を作らない規則（`docs/spec/01_orders.md` の 2 章）を保てる。

### 選択肢の出し直しは htmx の部分の応答にする

モダリティを変えたときの検査名・装置の選択肢と、間隔を変えたときの分の選択肢は、
`hx-get` で部分の HTML（`<option>` の並び）を受け取って差し替える。CSP は
`script-src 'self'` のままで、インラインの JavaScript は書かない。htmx が使えないときの
ために、最初の表示では既定のモダリティ（設定の先頭）と既定の間隔の選択肢を、サーバー側で
出しておく。

### 予約枠の刻みは設定に置く

予約作成には間隔の欄が無いので、分の刻みを設定の `orders.slot_minutes`（既定 15）で決める。
実際の RIS でも、予約枠の長さは装置や検査ごとの設定で決まり、予約のたびに入力しない。
値は 1・5・10・15・20・30・60 のどれかに限る（60 を割り切らない値では、時ごとに分の
並びが変わってしまう）。設定がこの範囲の外なら、起動しない（終了コード 2）。

### 一括作成の間隔は 60 を割り切る値に限る

画面の間隔は 1・5・10・15・20・30・60 分から選ぶ。今の画面は 0〜1440 分を受けるが、
60 を割り切らない間隔（例 45 分）では「間隔ごとの分」が時ごとに変わるので、選択肢を
固定できない。0 分（全件を同じ時刻にする）と 60 分を超える間隔は、CLI の `--interval` に
残す。

### 言葉の選び方

- 「全装置に振り分け」：予約を複数の装置に割り当てる業務の言葉として「振り分け」を使う
- 「新規（架空）」：RIS の患者の登録で使う「新規」に、架空の患者であることを括弧で添える
- 「名簿から無作為に」：一括作成の名簿の動きは無作為の抽出なので、それを言葉にする。
  予約作成の「名簿から選ぶ」と言葉を分ける
- 「ランダム」：依頼科を設定の候補から無作為に選ぶ。カタカナの一般の語で、数を連想させない
- 「登録」：業務アプリの確定のボタンの普通の言葉

## Risks / Trade-offs

- [`/orders/new` の中身が変わり、件数を入れて作る手順を書いた利用者の手順書が合わなくなる] →
  README と `docs/usage.md` の手順を一括作成に直す。一括作成への移り先を、予約作成の画面の
  ナビで見つけられるようにする
- [名簿が大きいと、選択肢が長くなる] → 名簿の例は5人で、試験用の名簿は数十人の想定。
  数百人を超えるなら、患者 ID の検索の欄を足す change を別に作る
- [`orders.slot_minutes` を足すと、設定の項目が1つ増える] → 既定値があるので、今の設定の
  ファイルはそのまま読める
