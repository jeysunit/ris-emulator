# Proposal

## Why

承認者が 2026-10-24 に予約を作る画面を見て、次の点を指摘した。

- 装置の選択肢「順に使う」の用途が想像できない
- 患者の選択肢「乱数で作る」は、作るのが数ではないので言葉が合わない
- 「名簿から選ぶ」を選んでも、名簿の患者を選ぶ欄が出ない
- 依頼科・文字コード・シードには項目の名前があるのに、患者の選択肢には無い
- 「シード」が何か分からない
- 開始時刻の分を、間隔に合わせて選べるようにしたい（15分なら 00・15・30・45、
  1分なら 00〜59）
- 画面が、作りたいデータの項目から作られていて、実際の予約の画面の流れになっていない。
  一般の予約は「日時・人・使うもの」を選ぶ

今の画面は、試験データを大量に作る道具（モダリティごとの件数・装置の振り分け・乱数の患者・
シード）と、1件の予約を作る画面を1つにしている。そのため、1件の予約を作る利用者にも
件数や振り分けの欄が見え、名簿の「選ぶ」は名簿から無作為に引く動きになっている。

公開の RIS の資料では、予約は患者を決めてから検査と装置（検査室）を決め、その装置の空いた
日時を選ぶ順で作る（design.md の Context）。

## What Changes

- **予約作成**（`/orders/new`）を、1件の予約を作る画面に組み直す。欄は次の順に並べる
  1. 患者：名簿から選ぶ（患者 ID・患者氏名・生年月日・性別を並べた選択肢）か、新しい架空の
     患者を作るかを選ぶ。項目の名前は「患者」
  2. 検査：モダリティを選ぶと、そのモダリティの検査名と装置の選択肢が出る。装置の既定は
     台帳の1台目
  3. 予定：予定日と予定時刻。時刻は時と分の選択肢で、分は設定の予約枠の刻み
     （`orders.slot_minutes`、既定 15 分）ごとに出す
  4. 依頼：依頼科（選択肢から必ず1つ選ぶ）と文字コード
  - 登録のボタンは「登録」。登録したら、その予約の詳細へ進む
- **一括作成**（新しい `/orders/batch`）に、今の件数を指定して作る機能を移す。ナビに
  「一括作成」を足す。画面の言葉を直す
  - 装置の「順に使う」は「全装置に振り分け」にする。台帳に装置が2台以上ある
    モダリティだけに、装置の選択肢を出す
  - 患者の「乱数で作る」「名簿から選ぶ」は、項目の名前「患者」の下の「新規（架空）」
    「名簿から無作為に」にする
  - 依頼科の「乱数で選ぶ」は「ランダム」にする
  - 開始時刻は時と分の選択肢にし、分は間隔ごとに出す。間隔の選択肢は 1・5・10・15・20・30・
    60 分（60 を割り切る値）にする。間隔を変えると分の選択肢を出し直す
  - シードの欄を画面から外す。CLI の `--seed` は残す
- CLI の `create` の引数と動き、MWL の応答、データベースの形は変わらない

## 承認者が決めること

1. 予約作成の欄の順
   - 案 A（推奨）：患者 → 検査と装置 → 予定日時 → 依頼。公開の RIS の予約の手引き
     （eRAD RIS）と同じ順で、空いた時刻は検査と装置が決まってから決まる
   - 案 B：予定日時 → 患者 → 検査と装置。承認者が挙げた一般の予約システムの順
2. 試験データを大量に作る機能の置き場所
   - 案 A（推奨）：別の画面「一括作成」に分ける。予約作成の画面を本物の予約の画面に近づけられ、
     一括作成の画面は試験の道具として言葉を選べる
   - 案 B：予約作成の画面に「1件」「一括」の切り替えを置く。画面は1つで済むが、切り替えの
     状態によって欄が出たり消えたりする
3. シード（同じ値なら同じ患者と検査を作る、乱数の種）の扱い
   - 案 A（推奨）：画面から外し、CLI の `--seed` だけに残す。同じデータを作り直す使い方は、
     試験の手順に書いて CLI で流すのが普通で、画面で使う場面が少ない
   - 案 B：一括作成の画面に「再現用の番号」の名前で残す

## Capabilities

### New Capabilities

- `order-entry`: 予約作成の画面（1件）と一括作成の画面の欄・順・選択肢・言葉

### Modified Capabilities

- `stations`: 予約の画面で装置を選ぶ要件を、予約作成（1台を選ぶ、既定は台帳の1台目）と
  一括作成（2台以上のときだけ選択肢を出す、既定は「全装置に振り分け」）に分ける

## Impact

- コード：`app/web/app.py`（`/orders/new`・`/orders/batch` と、選択肢を出し直す部分の
  ルート）、`app/web/templates/new_order.html`（予約作成に組み直す）、新しい
  `batch_order.html`、`base.html`（ナビ）、`app/services/order_service.py`
  （`OrderRequest` に検査のコードと名簿の患者 ID を足す）、`app/services/config.py`
  （`orders.slot_minutes`）、`config/app_config.yaml`
- テスト：`tests/web/`・`tests/services/` に、欄の順・名簿の患者を選ぶ・分の選択肢・一括作成の
  言葉の試験を足す。今の予約を作る画面の試験は、一括作成の画面の試験に移す
- ドキュメント：`docs/spec/03_web_cli.md` の 3.1 の表と 4 章の設定の表、
  `docs/spec/01_orders.md` の 1 章（検査名を選べること）と 3.2（名簿から選ぶこと）
- この change は `refine-order-list` の後に入れる（ナビの「予約作成」の言葉を共有する）
