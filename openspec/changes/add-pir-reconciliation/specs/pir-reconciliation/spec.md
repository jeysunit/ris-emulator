# Spec Delta

## Purpose

予約の無い撮影（MPPS だけが記録された撮影）に、正式な患者と新しい予約を結び、結果を
HL7 v2.3.1 で PACS に知らせる。PACS の PIR への対応を試す相手にするための照合の機能。

## ADDED Requirements

### Requirement: 予約に結び付いていない MPPS を未照合の撮影として一覧する

予約に結び付いていない MPPS を、未照合の撮影として、受けた順に一覧しなければならない
（SHALL）。一覧は、MPPS の状態によらず、仮の患者 ID・氏名・生年月日・性別、Study
Instance UID、モダリティ、予定の AE タイトル、受けた日時を示す。予約に結び付いた MPPS は
載せない。照合できない撮影（Study Instance UID か仮の患者 ID が無い、など）も載せ、理由を示す。

#### Scenario: 緊急の撮影の MPPS を受けた

- **WHEN** 一致する予約の無い項目の N-CREATE を受ける
- **THEN** 未照合の一覧に、仮の患者 ID・氏名・Study Instance UID・受けた日時が出る

#### Scenario: 予約どおりの撮影の MPPS

- **WHEN** 予約に結び付いた MPPS がある
- **THEN** 未照合の一覧に出ない

#### Scenario: 仮の患者 ID の無い撮影

- **WHEN** MPPS の Patient ID が空
- **THEN** 一覧には出て、照合の画面は「仮の患者 ID がありません」と示してフォームを出さない

### Requirement: 照合は撮影の Study Instance UID を保った新しい予約を結ぶ

未照合の撮影に正式な患者と新しい予約を結べなければならない（SHALL）。予約の Study
Instance UID は MPPS が持つ値をそのまま使い、新しく発番しない。予約の状態は MPPS の状態に
合わせ（`IN PROGRESS`=実施中、`COMPLETED`=完了、`DISCONTINUED`=中止）、結び付けた後に
届く N-SET が予約の状態を進める。予約の作成・MPPS との結び付け・照合の記録・送る HL7 の
組み立てを 1 つのトランザクションで行い、誤りがあれば何も残さず、連番も使わない。

#### Scenario: 照合を確定する

- **WHEN** 完了した撮影に、名簿の患者を指定して照合を確定する
- **THEN** 予約が完了で作られ、Study Instance UID は撮影のまま、MPPS が予約に結び付く。未照合の一覧から外れる

#### Scenario: 実施中の撮影に照合し、後で完了する

- **WHEN** `IN PROGRESS` の撮影を照合した後に、その MPPS の N-SET（COMPLETED）を受ける
- **THEN** 予約は実施中から完了になる

#### Scenario: すでに照合済みの撮影

- **WHEN** 照合済みの撮影をもう一度照合しようとする
- **THEN** 断り（画面は 409、CLI は終了コード 2）、予約も記録も増えない

#### Scenario: HL7 に入れられない値

- **WHEN** 氏名が空の患者で確定する
- **THEN** 入力の誤りで断り、予約も結び付けも残らず、次の照合の受付番号が欠番にならない

### Requirement: 照合の確定で HL7 を順に送り、受理されなかった 1 通で止める

確定の後、設定の宛先へ HL7 を 1 通ずつ順に送らなければならない（SHALL）。正式な患者 ID が
仮の患者 ID と違えば ADT^A40（PID が正式な患者、MRG が仮の患者）、同じで氏名・生年月日・
性別が違えば ADT^A08、すべて同じなら送らない。最後に ORM^O01（NW）を送る。患者区分
（PV1-2）は `E`。受理（AA）されなかった 1 通で止め、次の通は送らない。送信が拒否・失敗でも
照合は取り消さない。

#### Scenario: 患者 ID が違う

- **WHEN** 仮の患者 ID `ER2026102400` の撮影を、正式な患者 ID `P000001` で照合する
- **THEN** ADT^A40（MRG-1 が `ER2026102400`）、ORM^O01 の順に送り、ZDS-1 の先頭は撮影の Study Instance UID

#### Scenario: 患者 ID が同じで氏名が違う

- **WHEN** 仮の患者 ID と同じ ID で、氏名だけ違う患者で照合する
- **THEN** ADT^A08、ORM^O01 の順に送る

#### Scenario: 統合が拒否された

- **WHEN** ADT^A40 に AE か AR が返る
- **THEN** ORM^O01 は送らず「送信待ち」で残し、予約と結び付けは残る

#### Scenario: 宛先に接続できない

- **WHEN** 宛先に接続できない
- **THEN** 最初の通を「送信失敗」として記録し、照合は取り消さない

### Requirement: 送信の結果を記録し、受理されていない通を同じ本文で再送信できる

各通について、本文・MSH-10・結果・ACK の確認コードと理由・送信日時・送った回数を記録し、
予約の詳細に表示しなければならない（SHALL）。結果は「送信待ち」「送信完了」「拒否」
「送信失敗」とする。再送信は、受理されていない通を、記録した同じ本文（同じ MSH-10）で、
先頭から順に送る。受理済みの通は送らない。相手の ACK の制御文字は、記録と表示の前に
`\uXXXX` にする。

#### Scenario: 拒否の後に再送信する

- **WHEN** ADT^A40 が拒否された照合を、原因を直した後に再送信する
- **THEN** 前と同じ本文の ADT^A40 を送り、受理されれば続けて ORM^O01 を送る。両方が「送信完了」になり、再送信のボタンは消える

#### Scenario: 受理済みの通は送り直さない

- **WHEN** すべて受理された照合で再送信する
- **THEN** 何も送らない

#### Scenario: ACK に制御文字がある

- **WHEN** 相手の ACK の理由に ESC を含む文字が返る
- **THEN** 記録と画面には `\u001b` の形で出て、ESC そのものは出ない

### Requirement: 画面と CLI

画面は、ナビに「未照合」を置き、未照合の一覧（`/reconciliation`）と照合の画面
（`/reconciliation/<SOP Instance UID>`）を持たなければならない（SHALL）。照合の画面は、
撮影の値と、正式な患者（名簿から選ぶか入力する）・検査名・依頼科のフォームを示し、
「照合・送信」で確定して予約の詳細へ進む。誤りは同じ画面に示して入力を残す。
照合で作った予約の詳細には、照合前の患者 ID・氏名と、HL7 送信の表と、受理されていない
通があるときの「再送信」のボタンを出す。画面の項目の名前は screen-terms に従う。
CLI は `reconcile list`・`reconcile run`・`reconcile resend` を持ち、HL7 がすべて受理されれば
終了コード 0、拒否があれば 5、失敗があれば 6 を返す。

#### Scenario: 画面で照合する

- **WHEN** 利用者が未照合の一覧から「照合」を押し、名簿の患者を選んで「照合・送信」を押す
- **THEN** 予約の詳細へ進み、HL7 送信の表に ADT^A40 と ORM^O01 が「送信完了」で並び、照合前の患者 ID が出る

#### Scenario: 入力の誤り

- **WHEN** 入力する患者の患者 ID を空にして確定する
- **THEN** 400 で同じ画面に「患者 ID を入力してください」と示し、入力した値を残す。予約は作られない

#### Scenario: 照合していない予約

- **WHEN** 通常の予約の詳細を開く
- **THEN** 「HL7 送信」の表と「照合前」の項目は出ない

#### Scenario: CLI の終了コード

- **WHEN** `reconcile run` で ADT^A40 が AR で断られる
- **THEN** 終了コードは 5。`reconcile resend` で受理されれば 0
