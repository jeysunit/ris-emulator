# order-status Specification

## Purpose
予約の状態の種類と、状態を変更できる向きを定める。完了と取消は終わりの状態で、
その後は変更しない。MWL で返す状態もここで定める。

## Requirements

### Requirement: 予約の状態の種類

予約の状態は、予定（`scheduled`）・実施中（`in_progress`）・完了（`completed`）・
取消（`cancelled`）の4つでなければならない（SHALL）。MWL の応答の Scheduled Procedure Step
Status (0040,0020) は、予定を `SCHEDULED`、実施中を `STARTED` にする（PS3.3 C.4.10 の
Defined Terms）。

#### Scenario: 実施中の予約を MWL で返す

- **WHEN** モダリティが、実施中の予約に一致する C-FIND を送る
- **THEN** 応答の Scheduled Procedure Step Status は `STARTED` になる

### Requirement: 状態は遷移の表のとおりに変更する

予約の状態は、次の表で「可」とした向きにだけ変更しなければならない（SHALL）。
行が今の状態、列が変更後の状態。完了と取消は終わりの状態で、ほかの状態へ変更しない
（HL7 v2 の Table 0038 Order Status でも、CM（完了）と CA（取消）は終わりの状態）。

| 今の状態 | 予定 | 実施中 | 完了 | 取消 |
|----------|------|--------|------|------|
| 予定 | - | 可 | 可 | 可 |
| 実施中 | 可 | - | 可 | 可 |
| 完了 | 不可 | 不可 | - | 不可 |
| 取消 | 不可 | 不可 | 不可 | - |

#### Scenario: 予定から実施中へ変更する

- **WHEN** 利用者が、予定の予約を CLI の `status <受付番号> in_progress` で変更する
- **THEN** 予約の状態は実施中になり、終了コードは 0 になる

#### Scenario: 実施中から予定へ戻す

- **WHEN** 利用者が、実施中の予約を画面で予定に変更する
- **THEN** 予約の状態は予定になり、MWL の応答の Scheduled Procedure Step Status は `SCHEDULED` になる

#### Scenario: 完了の予約を予定に戻そうとする

- **WHEN** 利用者が、完了の予約を CLI の `status <受付番号> scheduled` で変更しようとする
- **THEN** 予約の状態は完了のままで、終了コードは 2 になり、標準エラーに今の状態と変更できないことが出る

#### Scenario: 取消の予約を実施中にしようとする

- **WHEN** 画面から、取消の予約の状態を `in_progress` にする POST が届く
- **THEN** 応答は 400 になり、予約の状態は取消のまま、更新日時も変わらない

### Requirement: 今と同じ状態への変更は何もしない

今と同じ状態を指定されたときは、予約を変更せずに成功を返さなければならない（SHALL）。
更新日時も変えない。完了・取消の予約に同じ状態を指定したときも成功にする。

#### Scenario: 完了の予約に完了を指定する

- **WHEN** 利用者が、完了の予約を CLI の `status <受付番号> completed` で変更する
- **THEN** 終了コードは 0 になり、予約の更新日時は変わらない

### Requirement: 遷移の検証は同時の変更でも破れない

状態の検証と書き込みは、1つのトランザクションの中で行わなければならない（SHALL）。
画面と CLI から同じ予約を同時に変更しても、遷移の表に無い向きの変更は保存されない。

#### Scenario: 取消と予定への変更が重なる

- **WHEN** 実施中の予約に、取消への変更と予定への変更が同時に届き、取消が先に保存される
- **THEN** 予定への変更は許さない遷移として断られ、予約の状態は取消のままになる

### Requirement: 画面は変更できる状態だけを選ばせる

Web 画面の予約の一覧と詳細は、今の状態と、今の状態から変更できる状態だけを選択肢に
出さなければならない（SHALL）。完了・取消の予約には選択肢を出さず、状態の名前だけを
表示する。

#### Scenario: 予定の予約の選択肢

- **WHEN** 利用者が、予定の予約を一覧で見る
- **THEN** 状態の選択肢は、予定・実施中・完了・取消の4つになる

#### Scenario: 完了の予約の表示

- **WHEN** 利用者が、完了の予約の詳細を開く
- **THEN** 状態は「完了」と表示され、状態を変えるフォームは表示されない

### Requirement: MWL で返す状態

MWL の SCP は、完了と取消の予約を C-FIND の応答に入れてはならない（SHALL NOT）。
返す状態は設定の `mwl.statuses` で選び、完了・取消を指定した設定は読み込まない。

#### Scenario: 完了にした予約が MWL から消える

- **WHEN** 予定の予約を完了にしてから、その受付番号で C-FIND を送る
- **THEN** 一致する予約は無く、Success だけが返る
