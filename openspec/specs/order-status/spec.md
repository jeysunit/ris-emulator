# order-status Specification

## Purpose

予約の状態の種類と、状態を変更できる向きを定める。完了と取消は終わりの状態で、
その後は変更しない。MWL で返す状態もここで定める。

## Requirements

### Requirement: 予約の状態の種類

予約の状態は、予定（`scheduled`）・実施中（`in_progress`）・完了（`completed`）・
取消（`cancelled`）・中止（`discontinued`）の5つでなければならない（SHALL）。MWL の応答の
Scheduled Procedure Step Status (0040,0020) は、予定を `SCHEDULED`、実施中を `STARTED` に
する（PS3.3 C.4.10 の Defined Terms）。取消は撮影を始める前の取り消し、中止は始めた撮影を
途中で止めたこと（MPPS の `DISCONTINUED`。PS3.3 C.4.14）を表す。

#### Scenario: 実施中の予約を MWL で返す

- **WHEN** モダリティが、実施中の予約に一致する C-FIND を送る
- **THEN** 応答の Scheduled Procedure Step Status は `STARTED` になる

#### Scenario: 中止を CLI で指定する

- **WHEN** 利用者が、実施中の予約を CLI の `status <受付番号> discontinued` で変更する
- **THEN** 予約の状態は中止になり、終了コードは 0 になる

### Requirement: 状態は遷移の表のとおりに変更する

予約の状態は、次の表で「可」とした向きにだけ変更しなければならない（SHALL）。
行が今の状態、列が変更後の状態。完了・取消・中止は終わりの状態で、ほかの状態へ変更しない
（HL7 v2 の Table 0038 Order Status でも、CM（完了）・CA（取消）・DC（中止）は終わりの状態）。
この表は、画面・CLI の手動の変更と MPPS による変更の両方に使う。

| 今の状態 | 予定 | 実施中 | 完了 | 取消 | 中止 |
|----------|------|--------|------|------|------|
| 予定 | - | 可 | 可 | 可 | 不可 |
| 実施中 | 可 | - | 可 | 可 | 可 |
| 完了 | 不可 | 不可 | - | 不可 | 不可 |
| 取消 | 不可 | 不可 | 不可 | - | 不可 |
| 中止 | 不可 | 不可 | 不可 | 不可 | - |

#### Scenario: 予定から実施中へ変更する

- **WHEN** 利用者が、予定の予約を CLI の `status <受付番号> in_progress` で変更する
- **THEN** 予約の状態は実施中になり、終了コードは 0 になる

#### Scenario: 実施中から予定へ戻す

- **WHEN** 利用者が、実施中の予約を画面で予定に変更する
- **THEN** 予約の状態は予定になり、MWL の応答の Scheduled Procedure Step Status は `SCHEDULED` になる

#### Scenario: 完了の予約を予定に戻そうとする

- **WHEN** 利用者が、完了の予約を CLI の `status <受付番号> scheduled` で変更しようとする
- **THEN** 予約の状態は完了のままで、終了コードは 2 になり、標準エラーに今の状態と変更できないことが出る

#### Scenario: 取消の予約を実施中にしようとする

- **WHEN** 画面から、取消の予約の状態を `in_progress` にする POST が届く
- **THEN** 応答は 400 になり、予約の状態は取消のまま、更新日時も変わらない

#### Scenario: 予定の予約を中止にしようとする

- **WHEN** 利用者が、予定の予約を CLI の `status <受付番号> discontinued` で変更しようとする
- **THEN** 予約の状態は予定のままで、終了コードは 2 になる

#### Scenario: 中止の予約を予定に戻そうとする

- **WHEN** 画面から、中止の予約の状態を `scheduled` にする POST が届く
- **THEN** 応答は 400 になり、予約の状態は中止のままになる

### Requirement: 今と同じ状態への変更は何もしない

今と同じ状態を指定されたときは、予約を変更せずに成功を返さなければならない（SHALL）。
更新日時も変えない。完了・取消の予約に同じ状態を指定したときも成功にする。

#### Scenario: 完了の予約に完了を指定する

- **WHEN** 利用者が、完了の予約を CLI の `status <受付番号> completed` で変更する
- **THEN** 終了コードは 0 になり、予約の更新日時は変わらない

### Requirement: 遷移の検証は同時の変更でも破れない

状態の検証と書き込みは、1つのトランザクションの中で行わなければならない（SHALL）。
画面と CLI から同じ予約を同時に変更しても、遷移の表に無い向きの変更は保存されない。

#### Scenario: 取消と予定への変更が重なる

- **WHEN** 実施中の予約に、取消への変更と予定への変更が同時に届き、取消が先に保存される
- **THEN** 予定への変更は許さない遷移として断られ、予約の状態は取消のままになる

### Requirement: 画面は変更できる状態だけを選ばせる

Web 画面の予約の一覧の選んだ予約の区画と詳細は、今の状態と、今の状態から変更できる状態だけを選択肢に
出さなければならない（SHALL）。完了・取消・中止の予約には選択肢を出さず、状態の名前だけを
表示する。

#### Scenario: 予定の予約の選択肢

- **WHEN** 利用者が、予定の予約を一覧で選ぶ
- **THEN** 状態の選択肢は、予定・実施中・完了・取消の4つになる

#### Scenario: 実施中の予約の選択肢

- **WHEN** 利用者が、実施中の予約を一覧で選ぶ
- **THEN** 状態の選択肢は、予定・実施中・完了・取消・中止の5つになる

#### Scenario: 完了の予約の表示

- **WHEN** 利用者が、完了の予約の詳細を開く
- **THEN** 状態は「完了」と表示され、状態を変えるフォームは表示されない

### Requirement: 終わりの状態へは確認の窓で確かめてから変える

Web 画面の選んだ予約の区画と詳細で、完了・取消・中止（終わりの状態）を選んで「状態を変える」を
押したときは、状態を変えずに、その状態の確認の窓（標準の `dialog`）を開かなければならない（SHALL）。
窓は、題を「受付番号（氏名・検査名）を〈状態〉にしますか？」、本文を「〈状態〉にすると、ワークリストに
出なくなります。状態は戻せません。」とし、照合で作った予約の取消・中止なら、送り先へ送る ORM^O01
（CA・DC）と、前の HL7 が受理されていないときは送らず送信待ちで残すことを書く。キャンセルを左
（初めのフォーカス）、実行「〈状態〉にする」を右に置く（取消・中止は危険の塗り）。

サーバーは、終わりの状態への変更を、窓の実行が付ける `confirmed=1` があるときだけ行わなければ
ならない（SHALL）。無ければ、htmx の要求は 400 で断り、画面の送信は窓を開いた形の詳細を出す。
実施中・予定への変更と、変えられない遷移の扱いは変わらない。CLI の `status` は窓を通らない。

#### Scenario: 取消の確認

- **WHEN** 利用者が照合で作った予約の詳細で取消を選んで「状態を変える」を押す
- **THEN** 状態は変わらず、窓に「取消にしますか？」と ORM^O01（CA）を送ることが出る。窓の「取消にする」で取消になる

#### Scenario: 窓を通らない変更

- **WHEN** `confirmed` を付けずに、htmx で完了への変更を送る
- **THEN** 400 で断り、状態は変わらない

### Requirement: MWL で返す状態

MWL の SCP は、完了・取消・中止の予約を C-FIND の応答に入れてはならない（SHALL NOT）。
返す状態は設定の `mwl.statuses` で選び、完了・取消・中止を指定した設定は読み込まない。

#### Scenario: 完了にした予約が MWL から消える

- **WHEN** 予定の予約を完了にしてから、その受付番号で C-FIND を送る
- **THEN** 一致する予約は無く、Success だけが返る

#### Scenario: 中止を返す設定

- **WHEN** 設定の `mwl.statuses` に `discontinued` を書いて起動する
- **THEN** 設定のエラーになり、起動しない
