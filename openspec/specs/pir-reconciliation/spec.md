# pir-reconciliation Specification

## Purpose

予約の無い撮影（MPPS だけが記録された撮影）に、正式な患者と新しい予約を結び、結果を
HL7 v2.3.1 で PACS に知らせる。PACS の PIR への対応を試す相手にするための照合の機能。

## Requirements

### Requirement: 予約に結び付いていない MPPS を未照合の撮影として一覧する

予約に結び付いていない MPPS を、未照合の撮影として、受けた順に一覧しなければならない
（SHALL）。一覧は、MPPS の状態によらず、仮の患者ID・氏名・生年月日・性別、Study
Instance UID、モダリティ、予定の AEタイトル、受けた日時を示す。予約に結び付いた MPPS は
載せない。照合できない撮影（Study Instance UID か仮の患者ID が無い、など）も載せ、理由を示す。

一覧の画面は、見出しの行（題「未照合」）の下に、件数の行（「n 件」と「受けた順」）、表の順に出す。
状態は MPPS の値をそのまま出さず、IN PROGRESS を「実施中」、COMPLETED を「完了」、DISCONTINUED を
「中止」と書いた状態の札にする。行の中の「照合」は高さ 24px の副のボタンにし、Study Instance UID は
列の幅を超えたら省略して、全文を `title` に持たせる。撮影が無いときは、表の見出しの行を残して、
空の状態（1 行目「未照合の撮影はありません。」、2 行目に次の手）を出す。

#### Scenario: 緊急の撮影の MPPS を受けた

- **WHEN** 一致する予約の無い項目の N-CREATE を受ける
- **THEN** 未照合の一覧に、仮の患者ID・氏名・Study Instance UID・受けた日時が出る

#### Scenario: 予約どおりの撮影の MPPS

- **WHEN** 予約に結び付いた MPPS がある
- **THEN** 未照合の一覧に出ない

#### Scenario: 仮の患者ID の無い撮影

- **WHEN** MPPS の Patient ID が空
- **THEN** 一覧には出て、照合の画面は「仮の患者ID がありません」と示してフォームを出さない

### Requirement: 照合は撮影の Study Instance UID を保った新しい予約を結ぶ

未照合の撮影に正式な患者と新しい予約を結べなければならない（SHALL）。予約の Study
Instance UID は MPPS が持つ値をそのまま使い、新しく発番しない。予約の状態は MPPS の状態に
合わせ（`IN PROGRESS`=実施中、`COMPLETED`=完了、`DISCONTINUED`=中止）、結び付けた後に
届く N-SET が予約の状態を進める。予約の作成・MPPS との結び付け・照合の記録・送る HL7 の
組み立てを 1 つのトランザクションで行い、誤りがあれば何も残さず、連番も使わない。

#### Scenario: 照合を確定する

- **WHEN** 完了した撮影に、名簿の患者を指定して照合を確定する
- **THEN** 予約が完了で作られ、Study Instance UID は撮影のまま、MPPS が予約に結び付く。未照合の一覧から外れる

#### Scenario: 実施中の撮影に照合し、後で完了する

- **WHEN** `IN PROGRESS` の撮影を照合した後に、その MPPS の N-SET（COMPLETED）を受ける
- **THEN** 予約は実施中から完了になる

#### Scenario: すでに照合済みの撮影

- **WHEN** 照合済みの撮影をもう一度照合しようとする
- **THEN** 断り（画面は 409、CLI は終了コード 2）、予約も記録も増えない

#### Scenario: HL7 に入れられない値

- **WHEN** 氏名が空の患者で確定する
- **THEN** 入力の誤りで断り、予約も結び付けも残らず、次の照合の受付番号が欠番にならない

### Requirement: 照合の確定で HL7 を順に送り、受理されなかった 1 通で止める

確定の後、設定の宛先へ HL7 を 1 通ずつ順に送らなければならない（SHALL）。正式な患者ID が
仮の患者ID と違えば ADT^A40（PID が正式な患者、MRG が仮の患者）、同じで氏名・生年月日・
性別が違えば ADT^A08、すべて同じなら送らない。最後に ORM^O01（NW）を送る。患者区分
（PV1-2）は `E`。受理（AA）されなかった 1 通で止め、次の通は送らない。送信が拒否・失敗でも
照合は取り消さない。

#### Scenario: 患者ID が違う

- **WHEN** 仮の患者ID `ER2026102400` の撮影を、正式な患者ID `P000001` で照合する
- **THEN** ADT^A40（MRG-1 が `ER2026102400`）、ORM^O01 の順に送り、ZDS-1 の先頭は撮影の Study Instance UID

#### Scenario: 患者ID が同じで氏名が違う

- **WHEN** 仮の患者ID と同じ ID で、氏名だけ違う患者で照合する
- **THEN** ADT^A08、ORM^O01 の順に送る

#### Scenario: 統合が拒否された

- **WHEN** ADT^A40 に AE か AR が返る
- **THEN** ORM^O01 は送らず「送信待ち」で残し、予約と結び付けは残る

#### Scenario: 宛先に接続できない

- **WHEN** 宛先に接続できない
- **THEN** 最初の通を「送信失敗」として記録し、照合は取り消さない

### Requirement: 送信の結果を記録し、受理されていない通を同じ本文で再送信できる

各通について、本文・MSH-10・結果・ACK の確認コードと理由・送信日時・送った回数を記録し、
予約の詳細に表示しなければならない（SHALL）。結果は「送信待ち」「送信完了」「拒否」
「送信失敗」とする。再送信は、受理されていない通を、記録した同じ本文（同じ MSH-10）で、
先頭から順に送る。受理済みの通は送らない。相手の ACK の制御文字は、記録と表示の前に
`\uXXXX` にする。

#### Scenario: 拒否の後に再送信する

- **WHEN** ADT^A40 が拒否された照合を、原因を直した後に再送信する
- **THEN** 前と同じ本文の ADT^A40 を送り、受理されれば続けて ORM^O01 を送る。両方が「送信完了」になり、再送信のボタンは消える

#### Scenario: 受理済みの通は送り直さない

- **WHEN** すべて受理された照合で再送信する
- **THEN** 何も送らない

#### Scenario: ACK に制御文字がある

- **WHEN** 相手の ACK の理由に ESC を含む文字が返る
- **THEN** 記録と画面には `\u001b` の形で出て、ESC そのものは出ない

### Requirement: 画面と CLI

画面は、ナビに「未照合」を置き、未照合の一覧（`/reconciliation`）と照合の画面
（`/reconciliation/<SOP Instance UID>`）を持たなければならない（SHALL）。照合の画面は、
撮影の値と、正式な患者（名簿から選ぶか入力する）・検査名・依頼科のフォームを示す。
「照合・送信」は確定せず、確認の窓を出す。窓の「照合・送信する」で確定して予約の詳細へ進む。
誤りは同じ画面に示して入力を残す。
照合で作った予約の詳細には、照合前の患者ID・氏名と、HL7 送信の表と、受理されていない
通があるときの「再送信」のボタンを出す。画面の項目の名前は screen-terms に従う。
CLI は `reconcile list`・`reconcile run`・`reconcile resend` を持ち、HL7 がすべて受理されれば
終了コード 0、拒否があれば 5、失敗があれば 6 を返す。

照合の画面は、画面の型 C（入力）の形で出さなければならない（SHALL）。上から、パンくず
（未照合 / 照合）、見出しの行、画面の上の知らせ、仮の患者の患者バナー（氏名・患者ID・
生年月日と性別・受付番号（「—」）・受けた日時・モダリティ。1 行の決まった形で、右端に「仮の患者」の
札と、MPPS の状態の札）、区画「受けた撮影」、
区画「正式な患者」「検査」、操作の行とする。MPPS の状態の札は、IN PROGRESS を「実施中」、
COMPLETED を「完了」、DISCONTINUED を「中止」と書く。操作の行の右端に、副の「キャンセル」
（未照合の一覧へ戻るリンク）と、主の「照合・送信」を並べる。

正式な患者の「名簿から選ぶ」「入力する」は、選んだ側の欄だけを押せる形にしなければならない
（SHALL）。サーバーは選んだ側の値だけを使う。送った名簿の患者が名簿に無いときは、名簿の先頭の
患者を選んだ形で出し直してはならない（SHALL NOT）。空の選択肢「選択してください」を選んだ形で出す。

#### Scenario: 照合の画面の形

- **WHEN** 利用者が未照合の撮影の照合の画面を開く
- **THEN** パンくず・患者バナー・3 つの区画・操作の行がこの順に並び、操作の行の右端に「キャンセル」「照合・送信」が並ぶ

#### Scenario: 画面で照合する

- **WHEN** 利用者が未照合の一覧から「照合」を押し、名簿の患者を選んで「照合・送信」を押し、確認の窓の「照合・送信する」を押す
- **THEN** 予約の詳細へ進み、HL7 送信の表に ADT^A40 と ORM^O01 が「送信完了」で並び、照合前の患者ID が出る

#### Scenario: 入力の誤り

- **WHEN** 入力する患者の患者ID を空にして確定する
- **THEN** 400 で同じ画面に「患者ID を入力してください」と示し、入力した値を残す。予約は作られない

#### Scenario: 照合していない予約

- **WHEN** 通常の予約の詳細を開く
- **THEN** 「HL7 送信」の表と「照合前」の項目は出ない

#### Scenario: CLI の終了コード

- **WHEN** `reconcile run` で ADT^A40 が AR で断られる
- **THEN** 終了コードは 5。`reconcile resend` で受理されれば 0

#### Scenario: 名簿から消えた患者

- **WHEN** 名簿に無い患者ID を「名簿から選ぶ」で送る
- **THEN** 400 で「名簿に無い患者ID です」と示し、名簿の患者の選択は「選択してください」を選んだ形で出る

### Requirement: 照合は確認の窓で確かめてから送る

照合の画面の「照合・送信」は、予約を作らず HL7 も送らずに、確認の窓（標準の `dialog`）を
出さなければならない（SHALL）。窓は、題を「仮の患者の氏名（患者ID）を 正式な患者の氏名（患者ID）に
照合しますか？」とし、仮の患者と正式な患者を並べた表（患者ID・氏名の漢字・かな・英字・生年月日・
性別・受付番号。値が違う行に「違う」の印）、作る予約の検査名と依頼科、送る HL7 の種類（ADT^A40
「患者の統合」・ADT^A08「患者の更新」・ORM^O01「予約」）と送り先（MSH-5 の受信アプリと
ホスト:ポート）を出す。統合を送るときは、この画面から取り消せないことを書く。キャンセルを左
（初めのフォーカス）、「照合・送信する」を右に置く。

窓は、出した内容（仮の患者・正式な患者・送る通・検査名・依頼科）の鍵を持ち、「照合・送信する」は
その鍵を付けて送る。確定のときに読み直した撮影で作った鍵が違えば（窓を出した後に N-SET で仮の
患者が変わった、など）、照合してはならない（SHALL NOT）。予約を作らず、「確かめた後に内容が
変わりました」と示して窓を出し直す。CLI の `reconcile run` は窓を通らない。

#### Scenario: 確認の窓を出す

- **WHEN** 利用者が名簿の患者を選んで「照合・送信」を押す
- **THEN** 予約は作られず HL7 も送られない。窓に仮の患者と正式な患者の表、ADT^A40 と ORM^O01、送り先、統合は取り消せないことが出る

#### Scenario: 確かめた後に撮影が変わる

- **WHEN** 窓を出した後に MPPS の N-SET で仮の患者ID が変わり、利用者が「照合・送信する」を押す
- **THEN** 予約は作られず、窓が新しい仮の患者で出し直される

### Requirement: 手で入れた患者ID を既にある患者と突き合わせる

照合の画面で「入力する」を選んだとき、入れた患者ID が名簿か既にある予約の患者のものなら、
その患者と、入れた氏名（表記ごと）・生年月日・性別を比べなければならない（SHALL）。両方に値のある
項目のどれかが違うか、氏名に両方に値のある表記が無ければ、確認の窓を出さずに 400 で断り、
既にある患者の氏名・生年月日・性別と、「名簿から選ぶか、患者ID を確かめてください」を示す。
合うときは、確認の窓の表に「既にある患者（同じ患者ID）」の列を足す。氏名は成分（姓・名）の
境目を保ち、空白と英字の大小を無視して比べる。名簿を読めないときは、手で入れた患者で照合しては
ならない（SHALL NOT。400 で断る）。CLI の `reconcile run` はこの突き合わせを行わない。

#### Scenario: 別人の患者ID

- **WHEN** 利用者が「入力する」で、名簿の P000001（田中 博）の患者ID と氏名 YAMADA TARO を入れて「照合・送信」を押す
- **THEN** 400 で「患者ID P000001 は、既にある患者（田中 博 1998/03/12 男）の患者ID です。」と示し、窓を出さない
