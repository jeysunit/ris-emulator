# ADR-0002: 予約の保存は SQLite にする

## ステータス

**Accepted** - 2026-10-21

## 背景

予約は、Web 画面（uvicorn のスレッド）、MWL の SCP（pynetdicom のスレッド）、
CLI（別のプロセス）の3つから読み書きする。保存先の候補は SQLite と JSON の
ファイルだった。

## 決定

1. **SQLite（Python の標準の `sqlite3`）にする。** 理由：別のプロセス・
   スレッドからの同時の書き込みを、ファイルのロックとトランザクションで
   守れる。JSON のファイルでは、CLI と画面が同時に書くと片方の書き込みが消える
2. 予約の中身は JSON の列（`body`）に入れ、絞り込みに使う値（受付番号・
   患者 ID・モダリティ・予定の AE タイトル・予定の日時・状態）だけを列に持つ。
   予約の形を変えても表を作り直さずに済む
3. 操作のたびに接続を開いて閉じる。WAL のモードにし、待つ時間は 10 秒
4. 受付番号の連番は `counters` の表で、作った日ごとに数える。
   連番の取得・予約の組み立て（文字コードの確かめを含む）・保存を
   1つのトランザクション（`BEGIN IMMEDIATE`）で行う。途中で断れば
   何も残さないので、連番に欠番ができず、乱数の患者 ID も同時の作成で重ならない

## 結果

- 追加の依存は無い
- 予約が数千件までなら、MWL の照合は全件を読んで Python で比べても足りる。
  それを超える使い方は想定しない（開発・試験用）
