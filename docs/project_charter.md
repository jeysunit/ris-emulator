# 目的と範囲

この文書は、ris-emulator が何のためにあり、何をしないかを決める。
今どう動くかは [spec](spec/) に、なぜその設計にしたかは [decisions](decisions/) に書く。

## 1. 目的

開発・試験の環境で、RIS の役を務める。架空の患者と検査の予約を作り、
MWL（Modality Worklist、C-FIND の SCP）で返す。モダリティがワークリストを取得し、
撮影して PACS へ送る流れの、前段を受け持つ。

## 2. 範囲

範囲に入れるもの：

- 予約を作る（CLI・Web 画面）。一覧を見て、状態を手で変える
- MWL の SCP
- Docker のイメージ

範囲に入れないもの：

- HL7 の受信
- Patient Demographics・帳票
- 本物の患者のデータ。施設の RIS・PACS・モダリティへの接続

まだ作っていないもの（MPPS など）は [roadmap.md](roadmap.md) にある。

## 3. 前提：DICOM と HL7 に違反しない

ris-emulator が返す値と振る舞いは、DICOM と HL7（v2・FHIR）の決まりに違反しない。
これは開発の前提で、ほかの都合と引き換えにしない。

- 規格の決まりに従って作った箇所は、spec に規格の節番号を書く
  （例 PS3.4 C.2.2.2、PS3.5 9.1）
- 規格が複数の形を許すときは、どれを選んだかを spec に書き、
  選んだ理由を ADR に書く
- 規格で確かめていないことは、確かめていないと spec に書く
