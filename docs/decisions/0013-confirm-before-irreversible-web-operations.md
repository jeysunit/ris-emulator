# ADR-0013: 画面の照合と終わりの状態への変更は、確認の窓を通したときだけサーバーが行う

- 状態：採用
- 作成日：2026-10-26
- 最終更新日：2026-10-26

## 背景

照合の画面の「照合・送信」は、1 回押すと照合を確定し、PACS へ ADT^A40（患者の統合）・
ADT^A08（患者の更新）・ORM^O01 を送っていた。統合は PACS の側で患者の記録を 1 つに
まとめる操作で、RIS の画面からは取り消せない。仮の患者と正式な患者を並べて比べる場所も
無かった。手で入れた患者ID は、名簿や既にある予約の患者と突き合わせていなかったので、
別人の患者ID を打ち間違えても、その患者ID への統合・更新を送っていた。

予約の状態の完了・取消・中止（終わりの状態）は戻せず、照合で作った予約の取消・中止は
ORM（CA・DC）を送る。これも選んで押すだけで確定していた。

## 決定

1. 照合の画面の「照合・送信」は確定せず、確認の窓（HTML の `dialog`）を出した画面を返す。
   窓に仮の患者と正式な患者の比べる表、送る HL7 の種類と送り先を出す。窓の「照合・送信する」が
   フォームの値を送り直したときだけ照合する。理由：送る通は照合のときの仮の患者で決まるので、
   サーバーが決めた通を、送る前に見せる必要がある
2. 窓は、出した内容（仮の患者・正式な患者・送る通・検査名・依頼科）の SHA-256 の鍵を持つ。
   確定のトランザクションで読み直した撮影から作った鍵と違えば、照合しない。理由：窓を出した
   後に N-SET で仮の患者が変わると、利用者が確かめていない統合を送ることになる
3. 「入力する」の患者ID が名簿か予約の患者のもので、氏名・生年月日・性別が合わなければ、窓を
   出さずに断る。合えば窓にその患者も並べる。理由：別人の患者ID への統合は、窓で見落とすと
   戻せない。正しく同じ患者を照合するなら「名簿から選ぶ」で足りる
4. 終わりの状態への変更は、確認の窓の実行が付ける `confirmed=1` があるときだけ行う。無い
   htmx の要求は 400 で断り、画面の送信は窓を開いた詳細を返す。窓はスクリプトが開く。
   理由：スクリプトが動かない・古い画面から送った変更でも、窓を通らずに確定しない

## 検討した選択肢

- 窓をスクリプトだけで作る（サーバーは今のまま）：送る通の種類と、手入力の患者ID の
  突き合わせはサーバーの値が要る。スクリプトが動かないと、確かめずに送る
- 手入力の既存の患者ID を、確かめの印（窓の中のチェック）で通す：design の決まり
  （窓の中に入力欄を重ねない）に反し、別人への統合を 1 回の操作で通せてしまう

## 結果

- 照合と終わりの状態への変更は、画面では必ず 2 回押す。窓の中身は送る通と一致する
- CLI の `reconcile run`・`status` は窓を通らず、手入力の患者ID の突き合わせもしない
  （試験の流れを自動で回す道具のため）
