# ADR-0011: 照合は MPPS に新しい予約を結び、Study Instance UID は撮影の値を使い、HL7 は同じ本文で送り直す

- 状態：採用
- 作成日：2026-10-25
- 最終更新日：2026-10-25

## 背景

予約の無い撮影は、モダリティが仮の患者 ID と氏名で撮影し、Study Instance UID も
モダリティが発番する。RIS には MPPS の記録だけが残る。後で正式な患者が決まると、
RIS は撮影に患者と予約を結び、PACS に HL7 v2 で知らせる（IHE の PIR）。

決めることは 3 つあった。照合した予約と MPPS をどう結ぶか。予約の Study Instance UID を
どちらが決めるか。HL7 の送信に失敗したときの扱い。

## 決定

1. **照合は、新しい予約を作り、MPPS の記録の「結び付いた受付番号」にその予約を足す。**
   MPPS の本体（N-CREATE と N-SET の属性）は変えない。結び付けたことで、後から届く
   N-SET が、既存の仕組み（ADR-0007）のまま新しい予約の状態を進める。結び付いた
   MPPS は未照合の一覧から外れ、2 回目の照合は断る
2. **予約の Study Instance UID は、MPPS が持つ値をそのまま使う。** PIR では、撮影した
   画像、MPPS、Procedure Scheduled の HL7 が同じ Study Instance UID で結ばれる。RIS が
   新しく発番すると、PACS にある画像と食い違う。[ADR-0004](0004-ris-issues-study-instance-uid.md)
   は予約を作るときの発番を定めたもので、予約の無い撮影はその例外として扱う
   （ADR-0004 は変えない）
3. **予約の作成・MPPS の結び付け・送る HL7 の組み立てを、1 つのトランザクションで行う。**
   HL7 に入れられない値（氏名が空など）は、確定の前に分かる。何も残さず、連番も使わない
4. **HL7 の送信は、トランザクションの後に行い、結果を記録する。** 通信の誤りや拒否で照合を
   取り消さない（予約と撮影の結び付けは RIS の中の事実で、PACS への知らせとは別）。
   組み立てた本文と MSH-10 を保存し、再送信は同じ本文で行う。受け手が MSH-10 で重複を
   見分けるときに、同じメッセージとして扱える
5. **受理されなかった 1 通で送信を止め、次の通は送らない。** 統合（A40・A08）が
   受理される前に、予約の知らせ（ORM）を送らないため

## 検討した選択肢

| 案 | 採らなかった理由 |
|----|------------------|
| MPPS を変えずに、予約と撮影を別の表で結ぶ | N-SET が届いても予約の状態が進まない。ADR-0007 の仕組みに載せ直す必要がある |
| 予約の Study Instance UID を RIS が発番し、撮影の値を捨てる | PACS の画像と UID が食い違い、PIR の「撮影の UID を残す」前提に反する |
| 送信が失敗したら、予約も取り消す | 照合の結果は RIS の中で確定している。PACS が止まっているだけで取り消すと、再送信できない |
| 再送信のたびにメッセージを組み立て直す | MSH-10 が変わり、受け手が重複を見分けられない |
| 全部のメッセージを、結果を待たずに送る | 統合が拒否されたまま ORM が届き、PACS の患者と予約が食い違う |

## 結果

- 照合した予約は、撮影が持つ Study Instance UID のまま、MWL を経由せずに作られる
  （完了・中止の予約は MWL で返さない。実施中は返す）
- 送信の状態（送信待ち・送信完了・拒否・送信失敗）が予約の詳細に残り、画面と CLI から
  再送信できる
- 送った本文を保存するので、データベースに患者の氏名が残る。架空の患者だけで使う前提
  （[project_charter.md](../project_charter.md)）

## 見直す条件

- 受け手が同じ MSH-10 の再送を重複として扱わない
- 照合を取り消したい要望が出る（今は終わりの状態への遷移と同じく、戻せない）
