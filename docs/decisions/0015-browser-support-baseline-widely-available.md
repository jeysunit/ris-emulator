# ADR-0015: 画面の対応ブラウザーは Baseline Widely available で決める

- 状態：採用
- 作成日：2026-11-14
- 最終更新日：2026-11-14

## 背景

Web 画面の対応ブラウザーを決めていなかった。画面は HTML・CSS・JavaScript を
ビルド工程なしで配るので、使う機能の線を決めないと、ブラウザーによって動かない
画面ができる。病院の端末はブラウザーの更新が遅れがちで、最新の版を前提にできない。
同じ線を、ウェブの画面を持つ製品のすべてに置くことを承認者が決めた。

## 決定

1. 対応の線は Baseline Widely available（主なブラウザーがそろって対応してから
   30 か月たった機能）にする
2. Widely available に入らない機能は、使えないブラウザーで壊れない退避を
   同じ PR で付けたときだけ使う
3. この製品はビルド工程を持たないので、線は spec の
   [3.4](../spec/03_web_cli.md) とレビューで守る。機能の日付は
   web-features のデータで確認する
4. 導入先が決まったら端末の実際の版で確かめ、線より古ければ対応を下げるか端末を更新する

## 検討した選択肢

- 最新のブラウザーだけを対象にする：更新が遅れた端末で動かない
- 端末の版を調べてから線を決める：導入先が決まるまで決められない。決まったときに
  線より古い端末が見つかれば、線を下げて見直す
- Baseline Newly available（Baseline low）を線にする：そろってから間もない機能を
  使うので、更新が遅れた端末で壊れるおそれが大きい

## 結果

- 新しい機能を使うときに、退避を作る手間が増える
- `browserslist` などの機械の検査は、ビルド工程を持たないので置けない。
  線に入らない機能の混入はレビューで見る

## 見直す条件

導入先が決まったとき、ブラウザーの更新が遅い端末が見つかったとき、半年ごと。
