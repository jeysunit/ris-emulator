# ADR-0010: HL7 v2.3.1 を自前で組み立て、漢字は UTF-8、氏名は表記ごとの繰り返しで送る

- 状態：採用
- 作成日：2026-10-24
- 最終更新日：2026-10-24

## 背景

PACS の PIR への対応を試すために、RIS から HL7 v2.3.1 の ADT^A40・ADT^A08・ORM^O01 を
MLLP で送る。決めることは 3 つあった。メッセージの組み立てに HL7 のライブラリを使うか。
漢字の氏名を、どの文字コードで送るか。英字・漢字・かなの 3 表記を、PID-5 にどう入れるか。
IHE RAD TF-2 は PIR を v2.3.1 で求める（Volume 1 の Table 4.1-1）。

## 決定

1. **メッセージは自前で組み立て、ライブラリを足さない。** 送る種類は 3 つで、セグメントの
   欄の位置と値の規則は IHE RAD TF-2 の表がそのまま決める。値は 1 つずつエスケープ
   してからつなぐ関数を `app/core/hl7.py` に置き、欄の位置は試験で固定する
2. **ASCII 以外の文字があるときは、UTF-8 で符号化して MSH-18 に `UNICODE UTF-8` を入れる。**
   IHE は文字集合の切り替え（MSH-20）を認めないので、ISO 2022 のエスケープ列で
   JIS X 0208 を混ぜる形は採らない。ASCII だけのメッセージは MSH-18 を空にする
   （IHE RAD TF-2 2.4.2.2）
3. **氏名は 3 表記を `~` でつないだ XPN の繰り返しにする。** 各 XPN の名前の種類を `L`、
   表記の種類を `A`・`I`・`P` にする。受け手が 3 表記を取り違えず、DICOM の PN
   （`英字=漢字=かな`）に戻せる
4. **送信の誤りは例外にせず、受理・拒否・失敗の結果で返す。** 後続の変更で、照合の
   結果を「送信に失敗した」と記録して再送するときに、呼び出し側が結果をそのまま保存できる

## 検討した選択肢

| 案 | 採らなかった理由 |
|----|------------------|
| HL7 のライブラリ（python-hl7 など）を使う | 種類が 3 つで、欄の位置の指定が主な仕事になる。依存を増やす利点が小さい。ライブラリは選んで調べていない |
| ISO IR87 のエスケープ列で漢字を送る | IHE が MSH-20 を認めない。受け手が文字集合を切り替える実装を持つ必要がある |
| 漢字だけを 1 つの XPN に入れ、英字・かなを捨てる | DICOM の氏名（英字・漢字・かな）を PACS の患者情報に戻せなくなる |
| 3 表記を 1 つの XPN のコンポーネントに並べる | XPN のコンポーネントは姓・名などで決まっており、表記の追加に使えない |

## 結果

- 追加の依存が無い。受け手は、MSH-18 と XPN の 8 つめの表記の種類で文字コードと表記を
  判断できる
- XPN の 8 つめ、CX の 5 つめの種類、`UNICODE UTF-8` は、HL7 v2.3.1 の原典で確認して
  いない（[spec/06_hl7_pir.md](../spec/06_hl7_pir.md) の 6 章）。受け手が読めない場合は、
  この ADR を見直す
- IHE の v2.3.1 の表にある欄の長さは守らない

## 見直す条件

- 受け手が表記の種類（XPN の 8 つめ）を読めない、または `UNICODE UTF-8` を受け付けない
- 送るメッセージの種類が増え、欄の位置の保守が負担になる
