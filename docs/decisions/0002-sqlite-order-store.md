# ADR-0002: 予約の保存先は SQLite にする

- 状態：採用
- 作成日：2026-10-21
- 最終更新日：2026-10-22

## 背景

予約は、Web 画面（uvicorn のスレッド）、MWL の SCP（pynetdicom のスレッド）、
CLI（別のプロセス）の3つから読み書きする。保存先の候補は SQLite と JSON
ファイルだった。

## 決定

1. **SQLite（Python 標準の `sqlite3`）にする。** 理由：別のプロセス・
   スレッドからの同時の書き込みを、ファイルのロックとトランザクションで
   保護できる。JSON ファイルでは、CLI と画面が同時に書き込むと片方の書き込みが失われる
2. 予約の内容は JSON の列（`body`）に格納し、絞り込みに使う値（受付番号・
   患者 ID・モダリティ・予定の AE タイトル・予定日時・状態）だけを列として持つ。
   予約の形式を変更してもテーブルを作り直さずに済む
3. 操作のたびに接続を開いて閉じる。WAL モードにし、待ち時間（タイムアウト）は 10 秒
4. 受付番号の連番は `counters` テーブルで、作成日ごとに数える。
   連番の取得・予約の組み立て（文字コードの検証を含む）・保存を
   1つのトランザクション（`BEGIN IMMEDIATE`）で行う。途中でエラーになれば
   何も残さないので、連番に欠番ができず、乱数で生成する患者 ID も同時の作成で重複しない

## 結果

- 追加の依存パッケージは無い
- 予約が数千件までなら、MWL の照合は全件を読み込んで Python で比較しても十分である。
  それを超える使い方は想定しない（開発・テスト用）
