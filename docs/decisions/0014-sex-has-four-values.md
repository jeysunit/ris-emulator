# ADR-0014: 性別は M・F・O・U の 4 値で持ち、DICOM に書くときだけ U を空にする

- 状態：採用
- 作成日：2026-10-31
- 最終更新日：2026-10-31

## 背景

性別の値は M・F・O と空の 4 通りで持ち、空は「不明」と「入力が無い」の区別がなかった。
画面は空のとき何も出さなかった。HL7 v2 の性別（表 0001）には不明を表す U があるが、
DICOM の Patient's Sex (0010,0040) の列挙値は M・F・O だけで、U は規格に違反する。
RIS は HL7 v2 を送り、MWL・MPPS で DICOM を扱うので、両方の規則に合わせる必要がある。
部品集（ui-kit 1.2.5）は、性別を M・F・O・U の 4 値とすることを 3 製品の共通の決まりにした。

## 決定

1. 画面と製品の中の値は M・F・O・U の 4 つにする。空で渡された値と、`Patient` を作るときに
   省いた値は U にする。4 つの外の値は断る
2. 画面は 男・女・その他・不明 と出す。値が空のときと 4 つの外の値のときも「不明」と出し、
   何も出さない画面を作らない。DICOM・HL7 の値は画面に出さない
3. HL7 v2 の PID-8 は U のまま送る
4. DICOM に書くとき（MWL の応答の Patient's Sex）は、U を空にする
5. DICOM から読むとき（MPPS の患者）は、空と M・F・O 以外の値を U と読む
6. 照合で「同じ患者ID の別人」かを見るとき、U は値が無いのと同じに扱う

## 検討した選択肢

- 内部の値を空のまま残し、表示だけ「不明」にする：入力と保存の側で、不明と未入力が
  区別できないままになる。3 製品で値の持ち方がそろわない
- DICOM にも U を書く：Patient's Sex の列挙値に反するので採らない

## 結果

- 保存済みの予約の空の性別は、読むときに U になる。保存形式の移行は要らない
- 照合で、MPPS が空の性別を送ってきても、予約の性別（M・F・O）と食い違う別人とは見ない
