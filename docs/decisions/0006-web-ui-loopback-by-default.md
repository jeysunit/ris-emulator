# ADR-0006: Web 画面は既定でループバックだけで待ち受け、それ以外のアドレスでは認証を必須にする

- 状態：採用
- 日付：2026-10-21
- 作成日：2026-10-22

## 背景

Web 画面では、予約を作成し、状態を変更できる。ユーザー管理の機能は無い。
ローカルの PC で実行するだけなら認証は不要だが、Docker イメージは外部から接続できるように
`0.0.0.0` で待ち受ける。認証なしでそのアドレスで待ち受けると、同じネットワークの
誰でも予約を書き換えられる。

ループバックで待ち受けていても、ブラウザー経由の攻撃経路が2つある。
DNS rebinding（攻撃者のドメイン名を 127.0.0.1 に名前解決させて、画面を
同一 origin として読み取る）と、別のサイトからの書き込み要求（CSRF）である。

## 決定

1. **既定は 127.0.0.1 で待ち受け、認証は設けない。** `Host` ヘッダーが
   ループバックの名前でなければ拒否する（DNS rebinding 対策）
2. **ループバック（127.0.0.0/8・`::1`・`localhost`）以外で待ち受けるときは
   HTTP Basic 認証を必須にする。** パスワードは環境変数 `RIS_WEB_PASSWORD_FILE` が
   指すファイルから起動時に1回読み込む。ファイルが無い、または読み取れないときは
   起動しない。ユーザー名は `ris` に固定する
3. 書き込み（POST）は、`Origin`（無ければ `Referer`）が同一 origin で、
   起動のたびに生成する CSRF トークンが送られたときだけ受け付ける
4. 応答に CSP（`default-src 'self'`、インラインスクリプトなし）などのヘッダーを付ける

## 検討した選択肢

| 案 | 採らなかった理由 |
|----|------------------|
| 認証を設けず、ネットワーク側で保護する | 待ち受けアドレスを変更した人が、認証の無いまま同じネットワークに公開しうる |
| ユーザー管理（アカウント・権限）を実装する | 開発・テスト用のツールには過剰。パスワード1つで足りる |

## 結果

- ローカルで実行するときは、設定なしで画面を使える
- ループバック以外で待ち受けるときは、パスワードのファイルを用意しないと起動しない
- 画面ではインラインスクリプトを使えない。htmx はリポジトリに同梱した
  ファイルから読み込む

## 決めないこと

- MWL の SCP の相手の認証。DICOM の Association では Called AE Title だけを
  検証し、Calling AE Title は検証しない（[spec/02_mwl_scp.md](../spec/02_mwl_scp.md)
  の 1 章）
