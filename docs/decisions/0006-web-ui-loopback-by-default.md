# ADR-0006: Web 画面は既定でループバックだけで待ち受け、それ以外のアドレスでは認証を必須にする

- 状態：採用
- 日付：2026-10-21
- 作成日：2026-10-22

## 背景

Web 画面からは、予約を作り、状態を変えられる。利用者の管理は持たない。
手元の PC で動かすだけなら認証は要らないが、Docker のイメージは外から届くように
`0.0.0.0` で待ち受ける。認証なしでそのアドレスで待ち受けると、同じネットワークの
誰でも予約を書き換えられる。

ループバックで待ち受けていても、ブラウザーから狙われる経路が2つある。
DNS rebinding（攻撃者のドメインの名前を 127.0.0.1 に向け直して、画面を
同じ origin として読む）と、別のサイトからの書き込みの要求（CSRF）である。

## 決定

1. **既定は 127.0.0.1 で待ち受け、認証は付けない。** `Host` ヘッダーが
   ループバックの名前でなければ断る（DNS rebinding よけ）
2. **ループバック（127.0.0.0/8・`::1`・`localhost`）以外で待ち受けるときは
   HTTP Basic を必須にする。** パスワードは環境変数 `RIS_WEB_PASSWORD_FILE` が
   指すファイルから起動のときに1回読む。無い・読めないときは起動しない。
   ユーザー名は `ris` に固定する
3. 書き込み（POST）は、`Origin`（無ければ `Referer`）が同じ origin で、
   起動のたびに作る CSRF の token を返したときだけ受ける
4. 応答に CSP（`default-src 'self'`、インラインのスクリプトなし）などのヘッダーを付ける

## 検討した選択肢

| 案 | 採らなかった理由 |
|----|------------------|
| 認証を付けず、ネットワークの側で守る | 待ち受けのアドレスを変えた人が、認証の無いまま同じネットワークに公開しうる |
| 利用者の管理（アカウント・権限）を持つ | 開発・試験用のツールには重い。パスワード1つで足りる |

## 結果

- 手元で動かすときは、設定なしで画面が使える
- ループバック以外で待ち受けるときは、パスワードのファイルを用意しないと起動しない
- 画面はインラインのスクリプトを使えない。htmx はリポジトリに置いた
  ファイルから読む

## 決めないこと

- MWL の SCP の相手の認証。DICOM の Association では Called AE Title だけを
  確かめ、Calling AE Title は問わない（[spec/02_mwl_scp.md](../spec/02_mwl_scp.md)
  の 1 章）
